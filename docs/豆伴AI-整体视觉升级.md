# 豆伴 AI · 整体视觉升级

2026-10-30。交付面是 `miniprogram/components/ai-assistant/` 的微信原生组件，不是旧浏览器原型。设计方向为“小窝信笺”：保留奶油粉绿、兔兔品牌与手账气质，以清晰正文、轻纸面和少量插画建立层级。

## 审计与方案

原组件的样式经过多轮追加，字阶、输入区与旧版卡片规则混杂。四个子页面的层级不一致：聊天、历史、设置与资料预览没有共同的页宽和操作规范；历史列表没有查找入口，列表视图还会下发长对话全文；设置默认展开多类资料和开关，保存操作需要滚到底部。

本次按任务重新安排结构，重建组件内样式，保留已验证的新对话、草稿、连续会话、停止生成、上下文筛选和滚动控制。代码仍是 WXML/WXSS/JS，无新增运行依赖，不更改服务地址策略、密钥保存规则、AppID 或生活记录。

## 四个界面的具体改造

| 界面 | 已落地的结构与视觉 | 参考与项目内取舍 |
| --- | --- | --- |
| 对话与空会话 | 固定页头的返回、新对话、更多各自独立；空会话使用原创兔兔信笺插图与两个明确的问题入口，已有密钥时不再重复配置引导。用户消息为粉色短笺，AI 回答为完整可长读纸面，时间与复制操作降为次级 | Vercel Chatbot 的消息流与有限建议入口；视觉沿用本项目手账，而不是复制其黑白外观 |
| 消息内容与输入区 | 段落、标题、列表、引用、代码拥有不同排版。代码横向滚动、保留语言标签、复制原文；输入、主动附图、模型提示、发送/停止在同一块信笺中。键盘弹起只缩减留白 | shadcn Input Group 的输入与工具整合、TDesign ChatSender 的顶部附件与底部操作分区；不加载 Web 组件库 |
| 我们的对话 | 搜索标题和最近消息摘要；当前会话用浅绿侧线与“正在聊”标记；摘要、时间、消息数各有层级。删除与打开使用分开的原生按钮 | Vercel 的会话索引思路，结合本机草稿和来源页返回规则；不是新增网页侧边栏 |
| 连接与资料 | 连接信息为首要任务；家庭资料授权、回答与历史偏好按需展开；已选范围计数跟随真实选择。保存栏独立固定，窄屏不需要滚到底部找保存 | TDesign 的受控表单与 ChatSender 配置边界；用本项目的色彩、触区和原生输入控件重做 |
| 发送预览 | 目的域名、字符数与会话条数先展示；历史文字、家庭资料正文默认折叠；展开后查看本次按当前配置构建的快照 | progressive disclosure。预览不触发请求，真正发送仍会重新读取记录，不暗示模型已经知道所有资料 |

## 统一 token 与组件职责

机器可读 token 见 `豆伴AI-design-tokens.json`。奶油 #FFF9F0、粉 #FFD9E8、绿 #C9E7D3、可可 #6B5B73 保留；AI 次级文字使用稍深的 #756272，提高浅绿与浅粉表面上的可读性。正文 14px、宽屏 15px，品牌字 17px，空会话标题 26px；手写仅用于品牌和少量标题，正文使用系统中文字体。阅读区最大 720px。

控件触区至少 44px，表单/按钮/消息/输入容器使用有层级的圆角；主要依靠留白、细边框和低对比底色，而不是厚阴影。只有等待状态的小圆点使用呼吸反馈；reduced-motion 下静态呈现。没有持续漂浮、紫蓝光球、虚假打字或自动循环装饰。

组件保留一个原生注册边界：模板内的 Header、Conversation、Composer、History、Settings、Context 负责展示；`index.js` 负责页面状态与现有会话逻辑；`utils/ai-markdown.js` 只输出安全文本块。没有为了拆分而新增全局组件或运行依赖。

## 实用功能与性能

1. 会话搜索匹配标题和最近消息的前 100 个字符；不宣称全文搜索。清空搜索恢复全部列表，切回会话恢复未发送草稿。
2. 最后一条已完成的文字回答可“重新回答”，沿用现有重试链路替换最后一轮并带上更早历史。附图回答不能暗中重传旧原图，需主动再次选图。
3. 列表只下发轻量元信息，全文按原会话读取，避免列表同时重复携带完整历史。
4. 资料范围默认折叠并显示真实选择数量；高级偏好默认折叠。连接费用、本机密钥保存方式、真机合法域名要求仍明确说明。
5. 代码保留围栏语言；未闭合的流式代码块也能显示、复制。模型 HTML、链接与代码仍作为文本，不执行。

## 交互与返回

- 对话页返回会话列表；列表返回原小程序页面；设置回对话且不保存修改；资料预览返回进入它的页面。
- 更多展开时，返回先收起菜单。更多位于页头下方，不使用阻挡新对话的全屏遮罩。
- 新对话始终为页头独立入口。生成中新建仍会终止旧请求，保存部分回答，迟到响应不能进入新会话。
- 空输入/测试中/准备附图时，发送使用语义 disabled 和可见状态；流式时发送改为停止；失败保留实际已收到的文字并提供重试。
- “回到最新”保留绝对定位和独立消息区，显隐不改变消息区高度。程序滚动、键盘重排与用户上滑仍使用原有保护逻辑。

## 验证与证据边界

- 完整原生回归：9 页 / 7 组件、绘图管线、13 组业务、22 组 AI/照片、15 组聊天可用性、9 组风格/打卡通过。
- 新增检查：会话搜索与草稿恢复、完成回答重新生成与附图边界、授权折叠与计数；代码标签、未闭合代码与不执行 HTML 纳入检查。
- 官方 wcc / wcsc 检查覆盖 16 个 WXML、21 个 WXSS。最终源码和素材体积以命令输出为准，不把源码字节数当上传包体。
- 排版样张由实际 WXML/WXSS 生成，使用隔离示例数据；Playwright 检查 320/390/900px 的横向边界、页头新对话 44px、菜单位置、保存栏、focus、reduced-motion 与最新按钮前后几何稳定。样张、报告在 `output/playwright/ai-20261030/`。
- 样张是浏览器对原生模板的离线排版近似，不是微信运行截图，不能替代原生键盘、真机安全区、读屏或帧率验收。本次没有操作用户桌面、读取模拟器存储或调用真实 AI 服务。

## 在微信开发者工具查看

打开当前项目，完整点击一次“编译”，从任意页面点右下贴边的豆伴书签。旧地址 `http://127.0.0.1:5188/#/ai` 是辅助 Web 原型，不是本轮原生交付面。

重点体验：空会话选择问题 → 编辑并发送；更多 → 我们的对话 → 搜索/恢复草稿；更多 → 连接与资料 → 展开授权/保存；长回答上滑 → 回到最新 → 新对话。不要通过清空本机存储来刷新界面。
