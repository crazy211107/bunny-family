# 豆伴 · 原生对话栏与连续会话修正

> 后续可用性修复以 `豆伴可用性审计与修复.md` 为准：顶部固定新对话，资料与轮数收进更多，不再常驻输入区元信息条；修复回到最新时的滚动反馈循环。以下保留此前记录。

2026-10-29。对应用户反馈：对话栏不好看，同一会话似乎无法承接前后文。

## 界面

主实现仍为 `miniprogram/components/ai-assistant/`，不改成网页。正文使用清晰的系统字体，手写字只用于品牌标题；保留奶油白、樱花粉、薄荷绿、可可文字与原 bunny-mark。

- AI 回答为轻纸卡，用户消息为右对齐粉色气泡；作者、时间、正文、资料数量和复制操作有独立层级。
- 输入框和工具按钮收进一个圆润信笺区；薄荷色箭头发送，粉色方块停止。空输入禁用发送。
- 收起重复说明和常驻“已完成”横条；真实错误、输出达到上限和停止提示仍保留。
- 顶部明确返回箭头保留：会话 → 会话列表 → 来源页；收起、新建、设置独立。
- 键盘弹出时收起次要信息，长正文与代码可复制，减少动态效果设置仍生效。

## 前后文

旧实现只携带最近六轮完整问答；长文字的预算处理会停止装入更早历史，附图/中断问答也被整轮排除。新实现携带最多十五轮，单次总消息数不超过中转约定的 32 条。

普通历史预算 20000 字符，当前附图时 8000 字符。长轮次按预算截取首尾并标明省略，保留近期各轮而不是整轮丢弃。中断的部分回答标注未完成。附图问答只保留文字，不重新发送图片。系统提示明确要求承接“刚才那段”“继续”“改短”等追问。

输入区显示可携带轮数；点击可查看会随下一次发送的实际历史文字，以及节选、过早轮次和资料范围过滤说明。只继承当前会话，不串到新会话。历史来自本机，既不是服务商自动记忆，也不是永久无限记忆。

关闭资料范围时，相关旧问答和由它们改写出的后续问答均不发送。旧版记录没有继承元信息，仍按保守规则过滤；不为恢复聊天而扩大资料授权。

## 验证

`npm run verify:ai`：22 组隔离检查，包括实际请求中的连续追问、重新打开会话、会话隔离、十五轮限制、长文首尾与 emoji、停止后继续、附图不重传、范围继承过滤与旧记录兼容。测试用假请求，不使用真实密钥。

`npm run verify:miniprogram` 和 `npm run verify:native-compile` 用于页面/业务回归与微信官方 WXML/WXSS 编译。未取得本轮真机截图，没有调用用户的真实 AI 服务，不能把桩检查等同真实模型效果。

微信开发者工具重新编译后，在同一会话先让豆伴写一段带指定署名的留言，再问“改短一点，保留刚才的署名”；输入区可查看实际附带的上文。
