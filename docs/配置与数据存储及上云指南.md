# 配置、数据存储与后续上云指南

[返回项目首页](../README.md)

本指南分为「当前可配置」「当前实际存储」「后续上云规划」。**云端部分尚未接入代码**，没有创建云资源或迁移任何真实资料。

## 一、确定使用方式

| 使用方式 | 当前需要什么 | 是否跨设备共享 |
| --- | --- | --- |
| 本地家庭手账 | 开发者工具、有权限的 AppID | 否 |
| 手账 + AI 直连 | 上述条件 + 服务商 Key、模型与合法域名配置 | 否 |
| 手账 + AI 中转 | 上述条件 + 服务端、HTTPS 接入与中转令牌 | 否，中转仅转发 AI 请求 |
| 家庭云端共享 | 另行开发登录、家庭权限、数据库、文件存储、迁移与同步 | 完成后才支持 |

**AI 中转不是数据同步服务，改环境变量也不会自动给本地手账加上云能力。**

## 二、当前如何配置

### 2.1 微信项目

根目录 `project.config.json`：

| 字段 | 当前值 / 规则 |
| --- | --- |
| `compileType` | `miniprogram` |
| `miniprogramRoot` | `miniprogram/` |
| `appid` | 维护原项目保留原值；Fork 使用自己有权限的 AppID |

AppID 是项目标识，不是 AppSecret。AppSecret、云访问密钥、供应商 Key 不放前端配置。开发者工具个人设置 `project.private.config.json` 已加入仓库忽略规则。

当前 `app.json` 注册 9 页，使用自定义导航和按需注入。调整布局保留顶部胶囊安全区与明确返回入口，不随意增加 `style: "v2"` 改变既有控件效果。

### 2.2 风格、照片与初始化资料

| 修改目标 | 位置 |
| --- | --- |
| 共享颜色、圆角等变量 | `miniprogram/styles/tokens.wxss` |
| 排版、复用形态、响应式 | 同目录 `base.wxss` / `components.wxss` / `responsive.wxss` |
| 页面特有样式 | `miniprogram/pages/<页面>/index.wxss` |
| 首次初始化的档案与示例照片 | `miniprogram/utils/store.js` 中 `initial()` |
| 内置图片 | `miniprogram/assets/photos/` |

**改初始化默认值不能可靠地修改已有记录。** 已有资料从页面编辑，或编写经过验证的迁移；不要通过清空 Storage 强行重置。豆米 / 豆糕沿用 `qiu` / `dou`，昵称可改，历史 ID 不随昵称变化。照片、日记和打卡都可能引用这些 ID。

更换家庭照片时同时检查 README 展示图和授权说明。字体默认走设备回退，打包字体文件前自行确认许可。

### 2.3 豆伴直连

小程序打开「豆伴 → 更多 → 设置」，选择直连：

| 设置 | 怎么填 |
| --- | --- |
| Base URL | HTTPS 兼容 API 地址，默认 `https://api.deepseek.com` |
| 模型 ID | 账户实际可用的模型；代码默认 `deepseek-flash` 不是可用性保证 |
| API Key | 自己的服务商密钥，在设置内输入，不写入 Git |
| 输出长度、temperature | 按需要设置，受客户端与服务商限制 |
| 资料范围 | 按用途选择，发送前检查资料预览 |
| 记住密钥 | 默认关闭；开启后写本地，共享设备不建议开启 |
| 附图能力 | 需实际模型支持，开启入口不代表模型能够识图 |

直连适合个人自用，不能安全隐藏一个所有用户共享的 Key。多人发布应由服务端持有 Key，并验证用户身份和配额。

### 2.4 AI 中转

在根目录执行：

```powershell
Copy-Item server/.env.example server/.env
# 在编辑器填写自己的配置，再启动
npm run ai:relay
```

| 环境变量 | 用途 |
| --- | --- |
| `AI_API_KEY` | 必填，服务商密钥，仅留服务端 |
| `AI_BASE_URL` | 上游 HTTPS Base URL，默认 `https://api.deepseek.com` |
| `AI_MODEL` | 实际可用的上游模型 ID |
| `BUNNY_RELAY_TOKEN` | 必填，中转访问令牌；24–256 个无空格可打印字符，与供应商 Key 不同 |
| `HOST` | 默认 `127.0.0.1`，程序仅允许回环监听 |
| `PORT` | 默认 `8788` |

客户端切换中转模式，Base URL 填实际地址，例如 `https://ai.example.com/v1`；令牌填对应的 `BUNNY_RELAY_TOKEN`。该域名仅是格式示例，仓库没有部署它。

供应商 Key、模型与上游地址由服务端决定，客户端不能任意覆盖。`GET /health` 只说明进程可达，不说明供应商 Key 已验证。

**部署顺序：**

1. 部署中转并填服务端密钥，保留回环监听。
2. 配置 HTTPS 反向代理，关闭 SSE 缓冲，设置足够的长连接超时。
3. 配置微信 request 合法域名，在手机真实网络验证。手机无法访问开发电脑的 `127.0.0.1`。
4. 检查代理 / 云平台是否记录正文、令牌或家庭资料，按需要关闭敏感日志。
5. 多人接入前增加登录校验、按用户配额与家庭授权；单个共享令牌不是生产用户体系。

详细接口限制见 [中转协议](../server/README.md)。平台认证、备案、类目与费用按发布时的规则核对，不使用历史价格作承诺。

### 2.5 本地检查配置

```powershell
npm ci
npm run verify:miniprogram

# 仅在官方编译器不处于默认目录时设置
$env:WECHAT_COMPILER_DIR = 'D:/path/to/wechat-devtools/code/package.nw/node_modules/wcc-exec'
npm run verify:native-compile
```

脚本默认编译器路径是原开发机目录，新机器需调整。未配置编译器时可在微信开发者工具中编译；无须为此修改业务代码。

## 三、当前数据存在哪里

### 3.1 业务资料

`miniprogram/utils/store.js` 使用 `wx.getStorageSync / wx.setStorageSync`：

```text
bunny-family-native-v1
├── version: 1
├── pets / members / photos
├── checkins / todos / notes
├── videos / editorDrafts
├── carePlans / planLogs / supplies
├── albums / diaryDraft
└── handover
```

`photos` 保存 ID、路径、标题、日期、关联兔兔等元信息，不应把图片二进制塞入这份 JSON。兼容逻辑补齐旧资料缺少的集合，不把缺字段当作重置资料的理由。

`store.update()` 先复制状态，再修改并写入 Storage；写入失败不提前污染缓存。云端改造也要保留相同的失败反馈。

### 3.2 媒体与作品

- 内置照片来自 `/assets/photos/...`，并未上传到云端。
- 导入照片优先持久保存到 `wx.env.USER_DATA_PATH`，失败时有兼容回退。选择器临时路径不能当成永久备份。
- 视频草稿保存原片段与编辑参数，文件失效时应提示，不宣称生成了成片。
- 系统相册里的导出成品不能还原原照片关联、日记与工坊图层。
- 本地路径只适用于当前设备，把路径写进云数据库也不能让家人手机读取文件。

文件配额、权限和保留规则受平台约束，不把某个历史容量数字当成跨版本保证。读取失败需有反馈，不能静默删除资料。

### 3.3 AI 数据

| Storage 键 | 内容 |
| --- | --- |
| `bunny-ai-settings-v1` | 模式、模型、范围等设置；明确选择记住后才含 Key |
| `bunny-ai-history-v1` | 保留历史时的会话与消息 |
| `bunny-ai-position-v1` | 浮标位置 |

Key 默认仅运行时内存。对话保存在本地不代表供应商没收到它：主动发送时，消息与选中资料仍经过对应服务。

### 3.4 备份与恢复

当前**没有完整备份导入 / 导出入口**。换设备、清理数据等操作可能导致记录无法恢复，开发者工具资料不是手机备份。

后续备份至少包括业务 JSON、媒体文件、版本号、文件清单与校验值，默认排除 Key、令牌和私有配置。恢复前预览差异，校验版本与媒体，失败保留原库；只导出 JSON 不等于完成媒体备份。

## 后续上云实施规划

> 以下为本项目的建议架构、拟议数据模型和验收顺序，不是已经存在的云接口或集合。

## 四、选择路线

| 路线 | 适合场景 | 需补齐能力 |
| --- | --- | --- |
| 微信小程序·云开发 | 主要在微信内家庭共享，减少后端运维 | 环境、云函数、数据库、私有存储、家庭权限与同步 |
| 独立 CloudBase | 逐步支持 Web / App 等多端 | 对应 SDK、身份体系、规则和存储适配，不能直接混用 `wx.cloud` |
| 自建 API + 数据库 + 对象存储 | 已有后端体系，希望自主控制 | 身份会话、API、签名上传、部署、监控、备份与更新 |

选择前核实账号、地域、计费单位、存储 / 流量预算，不承诺免费额度。本指南没有创建云资源，也不要求现在购买服务。

## 五、架构与改造点

```text
小程序页面
    ↓
异步业务数据层 ── 本地缓存 / 待同步队列
    ↓
云函数或 API ── 验证登录、家庭成员、输入、权限与版本
    ├── 数据库：业务记录与媒体元信息
    ├── 私有文件存储：照片、头像、视频、作品
    └── AI 代理：服务端密钥、资料范围、配额
```

建议新增数据访问层，分别适配本地与云端，页面处理 `loading / saving / offline / conflict / error`。当前 `store.js` 是同步接口，**不能只换成返回 Promise 的实现而不调整页面调用方**，否则会误报保存成功。

云环境初始化只是准备步骤，不等于实现登录、权限或同步。初始化方式按选定 SDK 官方文档接入；环境 ID 不是密钥，也不代替成员授权。

### 如果选择微信小程序·云开发，怎样开始配置？

以下是后续开发时的操作顺序，**现在还不能按此获得完整同步功能**：

1. 用自己的 AppID 在微信开发者工具进入云开发，确认该账号可开通的环境、地域与计费，建立独立开发环境；正式环境不要与测试共用资料。
2. 记录实际环境 ID，在计划新增的配置模块中区分开发 / 正式环境。不要将环境 ID 与服务端管理密钥混淆，不把管理密钥打进包。
3. 在未来版本的 `app.js` 启动流程中初始化该体系的 `wx.cloud`。最小调用形态如下，仅说明初始化位置，不包含任何同步实现：

   ```javascript
   // 后续接入示意，不是当前仓库已有代码
   wx.cloud.init({ env: '替换为自己的开发环境ID' });
   ```

4. 新建云函数目录并配置对应的 `cloudfunctionRoot`，实现身份与家庭成员校验；部署函数、安装其服务端依赖。当前仓库尚无这些业务云函数。
5. 按下一节建立集合 / 索引和私有文件存储，先以拒绝未授权访问为基线，再放通经过成员校验的业务操作。
6. 实现上传接口、文件 ID 映射和异步数据层，逐页接入加载 / 保存 / 错误状态；再做小批量迁移演练，最后才启用正式数据同步。

若选择独立 CloudBase，按对应 SDK 的初始化与认证流程实施，不复制上述 `wx.cloud` 示例。两条路线需先选定，再统一客户端与服务端依赖。

## 六、数据库如何拆分

下列名称和字段是拟议模型：

| 集合 / 表 | 对应资料与用途 |
| --- | --- |
| `users` / `families` | 平台身份映射、家庭空间、所有者与状态 |
| `family_members` | 用户和家庭的权限关系、邀请、退出；与手填家庭成员资料分开 |
| `pets` / `members` | 保留当前档案 ID 和展示资料 |
| `photos` / `albums` | 元信息、私有文件 ID、相册与引用关系 |
| `notes` / `todos` | 日记、标签、关联照片与待办 |
| `checkins` | 嵌套打卡拆为独立记录，保留原完成时间 |
| `care_plans` / `plan_logs` | 重复规则、指派、原始日期锚点与执行记录 |
| `supplies` / `supply_movements` | 补给、单位和进出流水，避免并发覆盖库存 |
| `creative_drafts` / `video_drafts` | 编辑参数、素材引用、导出记录，不存文件二进制 |
| `handover` | 用户手填交接与联系方式，受家庭权限限制 |

业务记录建议加 `familyId`、稳定 ID、服务端时间、版本与软删除标记。私有 AI 对话默认不家庭共享，Key 不进入业务集合。

打卡幂等键采用“家庭 + 业务日期 + 兔兔 ID + 照顾类型”一类稳定组合，重试不重复打卡、不刷新原时间。**业务日期与完成瞬间分开保存**，避免 UTC 转换把记录挪到前一天。

索引按查询建立，例如家庭 + 日记日期、家庭 + 照片日期、家庭 + 打卡日期 + 兔兔。唯一约束和事务能力按选定数据库实现，不把关系数据库语法套到文档库。

## 七、家庭权限

1. 从服务端验证的平台身份识别用户，不信任前端传来的 `openid / userId`。
2. 校验用户是目标家庭的有效成员，再允许读取或修改该 `familyId` 的记录。
3. 可设置所有者、编辑者、只读成员；昵称不是权限角色。
4. 邀请令牌随机、限时、可撤销；退出后撤销数据与上传访问权限。
5. 照片用私有存储和受控文件引用 / 短时访问凭据，不以永久公开链接实现“家庭隔离”。
6. 云函数具有服务端权限时也必须自行校验家庭身份。**客户端数据库安全规则不能替代云函数业务授权。**

不能把集合设成“所有登录用户可读写”实现家庭共享。官方对客户端规则和服务端访问有明确区分，见 [CloudBase 安全规则](https://cloud.tencent.cn/document/product/876/41802)。

## 八、迁移现有资料

| 步骤 | 做法与失败处理 |
| --- | --- |
| 本地快照 | 备份业务 JSON、媒体、版本与校验清单，默认排除密钥 |
| 选择家庭 | 建立权限后明确选择目标空间，不自动上传到错误家庭 |
| 上传文件 | 保存原路径 → 云文件 ID 映射；不可读文件列出提示，不静默跳过 |
| 迁移记录 | 保留 `qiu / dou` 和其他历史 ID、时间、标签与关联；同 ID 不同内容给冲突预览 |
| 替换引用 | 头像、日记附图、相册封面、工坊照片槽与视频草稿都改为可解析引用 |
| 核对完整性 | 检查记录数、文件数、校验值、关联与草稿重开；不能只数 JSON 条目 |
| 确认切换 | 校验通过后用户确认；迁移中断按批次幂等续传，不重复导入 |
| 保留回滚 | 在明确保留期内保留本地快照，失败不删原资料、不标迁移完成 |

不要把整个本地 JSON 当作唯一云文档反复覆盖，多人编辑容易互相丢数据，也不利于权限与查询。

## 九、多端同步与冲突

- 本地缓存先展示，但标明同步状态；写操作有唯一 ID 和待同步队列。
- 服务端版本号 / 条件写入检测并发。日记冲突保留双方版本，不按设备时间静默覆盖。
- 打卡按幂等键合并；库存操作使用事务或原子更新并保留流水；图层草稿另处理内容冲突。
- 删除保留标记，避免离线端把已删除数据重新上传；回收与彻底删除分开。
- 服务端记录更新时间，业务日期仍保留原有含义。
- 文件先解除业务引用，经过保留期后再清理，不能删相册就删掉其他日记仍引用的照片。
- 断网队列退避重试、可暂停、可看错误；“已本地保存”和“已同步”使用不同反馈。

## 十、实施里程碑与验收

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| A · 完整备份 | 打包与恢复、媒体清单 | 无 Key；缺文件可见；恢复失败不覆盖原库 |
| B · 身份权限 | 登录、家庭、邀请、退出 | 跨家庭越权被拒，退出立即失效 |
| C · 私有媒体 | 上传、下载、引用映射 | 第二台设备可访问授权文件，链接失效可恢复 |
| D · 业务迁移 | 拆分记录、校验、断点续传 | 不重复、不丢 ID 与历史时间，草稿可重开、可回滚 |
| E · 多端同步 | 队列、版本、冲突 | 并发不丢记录，删除不复活，库存不覆盖 |
| F · 云端 AI | 用户鉴权、配额、授权资料 | 不越家庭读数据，客户端无供应商 Key，流式取消有效 |

上线前补齐环境隔离、数据库备份与恢复演练、预算告警、日志脱敏、账号注销 / 数据删除流程。这些是后续交付，不是仓库当前能力。
