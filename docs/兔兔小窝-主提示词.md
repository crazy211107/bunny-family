## 一、项目是什么

给一个养了两只兔兔（白兔「豆米」、黄兔「豆糕」）的小家庭做的**私人手账小程序**。

它是**一本会动的家庭映画册，也是实用的照顾手账**：把照片、日记、照顾日程、补给与交接整理成“小日子”的叙事。用户应当能快速完成记录，又愿意回来翻看。

- 技术栈：微信原生小程序（WXML / WXSS / JS），无框架、无 npm 依赖。
- 根目录：`miniprogram/`（`project.config.json` 已配 `miniprogramRoot`）。
- AppID：`wx29b2c77fb1341d1e`；基础库 3.17.3。
- 交付同时包含浏览器原型（`src/` React），但**小程序是主交付物**，两边不要求像素一致。
- 2026-10-29 的 Web SaaS 首页/工作台已从主入口撤下；`首页与功能页-重构方案.md` 为错误方向的历史记录，不能作为当前规范。首页和功能优化应落实在原生页面，保留既定配色、胶带拍立得、手写标题与故事目录。

## 二、设计系统（数值即规范）

### 颜色

| 用途 | 值 | 说明 |
| --- | --- | --- |
| 纸张底 | `#FFF9F0` | 全局背景 |
| 卡片面 | `#FFFCF5` | 比底色更亮一档 |
| 主色 樱花粉 | `#FFD9E8` | 主按钮、选中态、强调 |
| 辅色 薄荷 | `#C9E7D3` | 完成态、次按钮、正面反馈 |
| 强调 奶油黄 | `#FFE9A8` | 便签、湿度卡、记忆卡 |
| 正文 可可紫 | `#6B5B73` | 正文与标题，绝不用纯黑 |
| 次要文字 | `#806C7B` | 说明、时间、标签，避免粉底浅字 |
| 装饰浅色 | `#B39DAA` | 只用于装饰线、非必要印章，不承载关键说明 |
| 描边 | `#E2D1DA` | 所有卡片 1rpx 细边 |
| 链接/动作 | `#875873` | 文字按钮、可点文字 |
| 遮罩文字底 | `#3B3140` | 压在照片上的文字必须给底 |

**配色纪律**：粉=操作，绿=完成，黄=回顾。同一屏不出现第四种强调色。

### 字号阶梯（rpx）

| 层级 | 字号 | 用途 |
| --- | --- | --- |
| 封面名 | 52 | 兔兔档案封面、页面大标题 |
| 页面标题 | 44–48 | 各页 `.title` |
| 区块标题 | 31–34 | `.section-title`、卡片头 |
| 正文 | 28 | 输入、正文 |
| 正文小 | 24–26 | 列表内容、说明 |
| 辅助 | 21–22 | 时间、计数、标签 |
| 极弱 | 19–20 | 注释、单位、不再更小 |

**下限 19rpx**。低于此值在手机上不可读，任何"为了精致而缩小"的改动都算退步。

### 触控与间距

- 主按钮、表单提交、关闭与重要图标按钮至少 88rpx；筛选胶囊至少 80rpx。紧凑来自减少重复介绍和卡片留白，不缩小关键触区。
- 常规卡片内边距 22–24rpx；卡片间距 18–24rpx；区块间距 28–32rpx。正文至少 24rpx，说明通常 22rpx。
- 窄屏保留触区并允许换行；600px 以上内容宽度约束到 600px，抽屉采用安全区＋弹性滚动。
- 所有仅图标动作要有准确 `aria-label`。选中、完成、只读状态有文字或符号，不只改变颜色；尊重减少动效偏好。
- 圆角：卡片 `36/52/30/44`，按钮 `36/46/32/42`——四角不等，禁止全站同一圆角。

### 层次与动效

- 卡片阴影固定三段：内高光 `inset 0 1rpx 0 #ffffff`、硬投影 `5rpx 8rpx 0 #6b5b7309`、柔投影 `0 12rpx 26rpx #6b5b730a`。
- 页面进场：`page-in .34s cubic-bezier(.22,.9,.3,1)`，位移 14rpx。
- 按压：`scale(.97)`，120ms。
- 尊重 `prefers-reduced-motion`。

| 手账墙 | `pages/home/index` | 紧凑抬头+日期便签 → 叠纸照片与播放条 → 今日手账 → 往年今日 → 双兔照片卡 → 不对称照顾/周记票根 → 低补给提示 → 提醒、照顾计划、便签 → 胶片卷 |
| 兔兔档案 | `pages/pets/index` | 切换胶囊 → 浅色照片封面与档案票根 → 四项紧凑照顾格（窄屏两列）→ 7 天汇总/14 天热度 → 月历/场记 → 体重 → 健康提醒 |
| 家庭成员 | `pages/family/index` | 时间轴成员卡（头像/名字/角色/生日/关系）→ 编辑抽屉 |
| 小日子信笺 | `pages/diary/index` | 草稿信封 → 筛选/标签索引 → 心情分布 → 置顶优先故事卡 → 详情/编辑抽屉；输入自动暂存，退出可续写 |
| 回忆相册 | `pages/album/index` | 主题册封面横卷 → 相册/回收站 → 组合筛选/搜索排序 → 月分组卡片墙 → 全屏放映；批量加入、移出主题册、设置封面 |
| 创意工坊 | `pages/studio/index` | 画布 540×600rpx → 照片轨 → 五工具页签（模板/贴纸/涂鸦/文字/调色）→ 保存/导出 |
| 视频草稿 | `pages/video/index` | 三步创作引导 → 预览 → 片名/字幕/滤镜 → 草稿列表，明确不合成 MP4 |
| 照顾日程与补给 | `pages/care/index` | 一周日历 → 任务时间线/家人分工/今日完成撤销 → 重复计划收纳册；补给抽屉记录出入库和低库存 |

## 四、数据与存储

- 单一存储键 `bunny-family-native-v1`，版本 `version: 1`。
- 结构：`pets / members / photos / todos / notes / videos / editorDrafts / checkins`；增量增加 `carePlans / planLogs / supplies / albums / diaryDraft / handover`，旧记录保留，新集合默认空。
- 媒体文件写入 `USER_DATA_PATH`（约 200MB），**不用 `wx.saveFile`（仅 10MB 配额）**。
- 打卡键 `petId:YYYY-MM-DD`，值为四项（喂草/换水/铲屎/陪玩）的时间戳。
- 所有 `src` 必须是**包根绝对路径**（`/assets/...`）或 `wxfile://`；存量数据在 `store.get()` 里统一归一化。

## 五、已实现功能清单

**记录与照顾**：双兔独立打卡与撤销（真实时间）、月历回看、14 天照顾热度、连续天数、体重曲线、健康提醒、成员时间轴。

**照片**：多图上传、按月归档、标签/兔兔筛选、喜欢、多选批量、长按进多选、回收站恢复、全屏放映（自动播放 3.5s + 进度条 + 点击暂停）。

**创作**：八模板、四格拼贴、双重叠影、贴纸变换、四种笔刷、文字与字迹、调色（原生滤镜 + 逐像素回退）、30 步撤销、草稿、PNG 导出。

**叙事**：日记（心情/日期/双兔/照片/标签）、心情分布、去年的今天、今日场记、胶片卷。

**照顾分工**：一次、每日、每周指定星期、间隔天数计划；固定起始日锚点，迟打卡不顺延；家人指派、暂停、收起、今日完成/撤销，过去与未来只读。指派保存在本机，不发送通知。

**实用补给**：品名/单位/补货线/适用兔兔；默认零库存；最多三位小数出入库；不可负库存；保留流水；有流水后禁止直接换单位。

**整理与保护**：命名主题册、改名、独立封面、批量加入/移出；册子引用原照片。日记置顶、标签索引、自动草稿恢复/丢弃；编辑保留原 id，提交后清草稿，存储失败保留内容。

**回顾与交接**：周报只按已过去的天数计算照顾分母，排除未来和无日期照片；本周两次有效体重才给差值，不做健康推断。交接列未来三天未完成日程、补给与档案提醒、用户填写的特别说明/联系人；可复制完整文字或生成精简 PNG。分享的是快照。

## 六、硬约束（都是踩过的坑，别再踩）

1. **`app.json` 不得加 `"style": "v2"`**。v2 会让 `<button>` 默认铺满宽度，固定宽高的圆形控件会被拉成椭圆。
2. **固定尺寸的控件用 `<view>`**，配 `hover-class` 做按压；`<button>` 只用于带文字的表单动作。
3. **WXML 指令必须写 `{{ }}`**。`wx:if="journal"` 是字符串恒真，会让遮罩永远盖住页面、`wx:for="pets"` 直接渲染不出列表，且**编译器不报错**。
4. **微信右上角胶囊是原生控件**，层级高于任何 view。任何浮层头部都要避开：`safeTop = min(capsule.bottom + 8, statusBar + 48)`，且只加在 `.drawer` 本体上，**不要加到 `.drawer-head`**（会叠两层）。
5. **canvas 取图必须给前导斜杠**。`wx.getImageInfo` 返回的 `path` 会丢掉 `/`，直接喂给 `canvas.createImage()` 会既不 onload 也不 onerror，页面永远停在加载态。取图走候选链：绝对路径 → 原路径 → 复制到 `USER_DATA_PATH`。
6. **包内资源路径统一 `/assets/...`**，相对路径会被解析成 `pages/xxx/assets/...` 并 500。
7. **不编造数据**：没有体重、年龄、生日就如实留空；推导型回忆模块无数据不显示。可操作的工具空态要解释下一步并提供真实入口。
8. **WXML 逻辑运算符写 `&&`**，不要把 JS 表达式中的运算符写为 `&amp;&amp;`，官方 wcc 会报表达式错误。
9. **本机与云功能边界准确**：没有云同步与消息订阅。AI 需用户配置自己的服务/密钥，按选择范围发送本机资料，不能伪造模型回答或自动写入成功；视频为预览/草稿，不宣称能合成 MP4。

## 七、验收标准

改完必须依次通过：

```bash
node scripts/verify-miniprogram-pages.mjs   # 注册的 9 页装载、事件实现、WXML 指令与样式入口扫描
node scripts/verify-miniprogram.mjs         # 8 模板 / 调色双路径 / 笔刷等 10 组断言
node scripts/verify-family-features.mjs     # 13 组状态流、日期/库存/草稿边界及共享搜索检查
node scripts/compile-native.mjs            # 本机官方 wcc/wcsc，仅本地编译，不向微信传项目
```

截图验收：可用本地 `miniprogram-automator`，但本轮多个 SDK 接口持续超时，不能把连接成功当成渲染通过。`scripts/native-screens.cjs` 不写用户数据。官方二维码预览会将源码和素材传给微信服务，属于独立的外传步骤，需用户明确授权。

**验收纪律**：分开报告语法编译、隔离行为校验、模拟器截图、真机结果；没有截图的页面不声称已完成视觉验收。详见 `本轮验收记录.md`。

## 九、继续优化时可直接使用的执行提示词

在现有已适配的微信原生小程序中增量完善所有页面。先读本主提示词、代码和最新验收记录，再查看 Vant Weapp、TDesign 小程序、WeUI、Ant Design Mobile 的官方组件实现，选择适合原生场景的列表、表单、弹层、搜索、步骤与状态模式。将这些模式转为统一的原生组件与样式，保留豆米、豆糕真实照片和奶油可爱手账配色。

逐页优化封面/摘要/内容/操作的层次；通过减少重复信息与留白使界面紧凑，保留重要触区。全局复用按钮、搜索框、空态、输入、反馈与抽屉，处理加载、空数据、错误、只读、选中和完成状态。窄屏可换行，宽屏限制内容列，弹层避开系统胶囊与安全区。提供准确原生朗读名，状态不只依赖颜色，并支持减少动效。

实际实现双兔照顾、日程分工、补给、日记、主题相册、创意编辑、周记与交接的有效流程；数据未知时留空，本机功能如实说明。禁止加入传统底部导航、暗黑电影主题或与当前设计不协调的企业后台皮肤。完成后逐页列出改了什么、来源是什么、在代码哪里，以及哪些检查真正通过；编译、模拟器与真机结果分开报告。
