# 兔兔小窝 · 专家增强提示词与功能闭环

## 结论

产品交互专家与前端架构 / 代码审查专家共同审查后，当前原型的主要问题是：功能停留在新增与点击，没有形成「记录 → 回看 → 编辑 → 整理 → 再创作」的持续使用闭环。本轮保留已确认视觉，重点扩展真实能力，不靠多加装饰或伪造 AI 来增加功能感。

本稿应用 interaction-design 的状态反馈 / 可取消交互 / 低动效规则，backend-architect 的数据边界 / 一致性 / 幂等约束，以及 code-reviewer 的回归风险检查。

用户已确认：白色兔兔叫 **豆米**，黄色兔兔叫 **豆糕**。内部稳定 ID 暂继续使用 qiu / dou，以保留旧原型资料；所有界面与照片归属采用真实名字。

## 可直接复制的增强提示词

> 请以产品设计、交互设计和前端架构专家共同审查的标准，增强现有「兔兔小窝」微信小程序设计原型。严格保留奶油白 #FFF9F0、樱花粉 #FFD9E8、薄荷绿 #C9E7D3、奶油黄 #FFE9A8、可可紫 #6B5B73，可爱手账、非对称贴纸卡、真实兔兔影像、明亮的家庭映画叙事、故事目录和独立兔耳果冻 FAB 四项扇形菜单。禁止传统底部导航、暗色大片风和常规侧栏仪表盘。白色兔兔叫豆米，黄色兔兔叫豆糕。
>
> 不要只做一次性点击演示。请完善四个真实闭环：
>
> 1. **照顾与成长**：双兔独立四项打卡，按月查看照顾日历、点选历史日期看完成项与实际时间；展示真实完成率、连续天数和近七天统计。过去日期只读，未来不能打卡，不植入虚构历史。体重曲线与健康提醒继续保留。
> 2. **家庭日记**：日期、心情、兔兔关联、照片关联、标签、标题和正文；支持新建、详情、原 ID 编辑、标题正文搜索、日期 / 心情 / 兔兔筛选、可恢复删除。保留创建时间并记录更新时间，不能把编辑变成重复新建。
> 3. **回忆整理**：照片搜索与排序、按稳定 petId 筛选、资料编辑、ID 集合多选、批量喜欢与分类、回收站和恢复；多张上传有实际进度与单张失败反馈。放映仅在当前筛选集合内进行，删除当前或最后一张时正确退出或显示空状态。
> 4. **照片再创作**：八模板保留，四格可分别选择真实照片；双图曝光可选择第二张素材；加入撤销 / 重做、草稿保存与恢复、马克笔 / 荧光笔 / 虚线笔、马赛克。贴纸支持移动、缩放、旋转、删除。一次拖动或一条笔画只占一个历史步骤，最多 30 步。预览与导出复用同一管线，导出的 PNG 包含模板、调色、文字、贴纸与笔画，且没有编辑选框。
>
> 新功能必须和现有数据兼容，刷新不清空用户资料。照片 / 视频二进制继续存在 IndexedDB，结构化资料与编辑参数存在本机 store，所有记录通过稳定 ID 关联。删除先进入可恢复回收站。处理空集合、损坏资料、文件缺失、存储失败、换图失败、撤销后新分支等情况，不能用成功提示掩盖错误。
>
> 沿用同一响应式视觉系统，避免功能增加后变成密集后台。日记像信笺，照顾历史像打卡月历，相册像接触印样，编辑器像贴纸工作台。关键操作有明确结果和返回入口，支持键盘和低动效。原型只实现本地真实能力，微信登录、云同步、订阅消息、识别模型和 MP4 合成另行接入并如实标注。

## 一次对抗性复审必查

- 同日相同打卡操作不重复；双兔状态隔离；历史日期不被写成今天。
- 日记编辑保留 ID；关联照片删除后安全回退；过滤为空显示空状态。
- 相册选中项在过滤变化后不越权作用于隐藏项；恢复后同一 ID 不重复。
- 放映集合为空、当前照片被删除、照片数变化均不读 undefined。
- 撤销后进行新编辑会清除 redo；拖拽 / 滑杆 / 连续笔画不会塞满历史。
- 草稿只保存序列化参数，不保存 Canvas、Image 或对象 URL。
- 作品导出与预览共用绘制函数；马赛克只采样底层照片，编辑选框不导出。
- 不把源码 / 生产构建检查写成真机或浏览器视觉验收。

本稿优先于旧优化稿中与增强范围冲突的段落；视觉规则始终以用户最后确认的可爱手账方向为准。
