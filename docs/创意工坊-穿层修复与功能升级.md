# 创意工坊：目录穿层修复与编辑能力升级

本轮交付面向微信原生小程序，源码在 `miniprogram/`。沿用奶油信纸、樱花粉、薄荷绿、兔耳标识、拍立得和用户提供的豆米/豆糕照片。没有迁移 React 或改变全站导航，没有安装新的运行依赖。

## 1. 截图问题与修复

复现路径：进入创意工坊 → 等作品画布加载 → 点击右上“翻开目录”。用户截图中的大拍立得正是工坊作品；原实现只把目录的普通视图置顶，画布一直挂载，也没有页面隐藏、目录和 AI 浮层之间的生命周期协调。截图现象与原生画布穿层一致。本轮没有取得微信模拟器内部渲染层的现场追踪，不把具体引擎原因当作已证实结论。

现在不依赖更大的 z-index：

1. 目录和豆伴按各自组件实例登记浮层所有权。
2. 工坊结束当前笔画、提交当前文字编辑，使用 `wx:if` 卸载画布。
3. 等 `setData` 回调确认视图更新后，目录/豆伴才打开。
4. 最后一个浮层关闭后，重新查询 Canvas 节点、用新节点加载图片，再按内存中的参数绘制；草稿、笔画、图层和撤销栈保留。
5. 页面隐藏/卸载时取消旧加载令牌；迟到的节点查询和图片回调不能回填新画布。

多浮层同时存在、快速打开后关闭、页面跳转都有所有权与令牌保护。目录关闭后在原画布位置恢复，不滚动整页。未改动 AI 的连续上下文、发送、停止、新对话和滚动算法。

代码：`utils/overlay.js`、`pages/studio/index.js/.wxml`、`components/bunny-menu/index.js`、`components/ai-assistant/index.js`。

## 2. 实际新增能力

| 能力 | 本轮落地 | 可恢复性/边界 |
|---|---|---|
| 十套模板 | 原八套 + 双兔来信（双联）、三连拍票根；双联/三连/四格每镜头可独立换图 | 缺失副图回退主图，不修改原照片 |
| 照片构图 | 1–3 倍缩放，横纵取景，90° 旋转，水平/垂直翻转，直接拖动画布取景 | 自动限制到不露白范围；支持每镜头独立取景，或整组统一调整；整组调整覆盖独立设置但可撤销；可只重置所选取景 |
| 可移动文字便签 | 最多40字，保留换行并自动折行，字号、颜色、奶油纸底、拖动/坐标调整 | 与贴纸共用图层；字体按设备回退，不承诺设备上不存在的授权字体 |
| 批注和落款 | 批注扩展到40字、字号和配色；自定义页脚、日期选择/显示 | 日期模板固定显示日期；超出排版宽度时绘图省略，不破坏输入 |
| 六种手绘贴纸 | 兔耳、胡萝卜、爱心、星星 + 小花、纸胶带 | 原四种保留手绘配色；文字/小花/胶带可换色 |
| 图层抽屉 | 列表选取、复制、上移/下移、居中、锁定/解锁、隐藏/显示、移除 | 最多16个；锁定禁止拖动、修改及删除；列表可找回隐藏或被遮挡的图层 |
| 配色与纸张 | 原片、奶油光、旧胶片、小春日、黑白信；保留三滑杆微调；随模板或四种信纸底色 | 只处理照片层，保留原生滤镜与逐像素兼容路径 |
| 对照、撤销与草稿 | 查看保留模板的原片对照，30步撤销/重做；新参数与图层完整存入草稿 | 对照不改作品；旧草稿补默认字段；保存失败不污染旧草稿 |
| 导出 | PNG/JPG；900×1000、1350×1500；保存到回忆相册或手机相册 | 高清档真实按3倍逻辑像素绘制；不含编辑选框；JPG质量92%；手机保存依赖相册授权 |

导出格式/分辨率为当前编辑器选项，不写入生活记录；作品与草稿仍仅在本机保存。豆伴的应用目录已同步新能力；工坊草稿只有勾选相应资料范围后才进入 AI 上下文，AI不能直接操作工坊或替用户保存。

## 3. 交互与视觉

- 预览、工具、草稿三段布局；宽屏左右工作台，手机单列。
- 六工具以分段按钮组织，手机两行、宽屏单行，减少横向寻找和溢出。
- 模板缩略图显示真实的单帧/双联/三连/四格结构。
- 图层列表和导出设置默认折叠；选中对象才显示尺寸/位置等细调。
- 固定44px色板热区，宽屏不把 rpx 控件和说明文字无限放大。
- 提供“回看画布”直接定位；旋转后点击按逆变换命中，隐藏图层不抢触摸。
- 原片对照是明确的开/关按钮；保存时锁定编辑、防重复触发；空、加载、失败和不可操作状态有文字反馈。
- 按钮、输入和选择器有 focus 态，坐标滑杆提供拖动的替代操作；减少动态效果时无额外动画。

## 4. 参考来源与取舍

1. [TOAST UI Image Editor](https://github.com/nhn/tui.image-editor)：参考其画布居中、照片操作与对象操作分工，以及 crop/flip/rotate/text/filter/undo/export 的完整任务流程。本项目自行实现所需原生 Canvas 能力，没有引入 Web 编辑器或照搬其界面。
2. [TOAST UI ImageEditor API](https://nhn.github.io/tui.image-editor/latest/ImageEditor/)：参考对象选取/编辑与历史操作之间的职责划分；在原生中加入锁定、隐藏、坐标滑杆与折叠图层抽屉。
3. [腾讯小程序同层渲染说明](https://main.qcloudimg.com/raw/document/intl/product/pdf/tencent-cloud_1219_57619_en.pdf)：区分原生组件与普通视图，修复方案对原生层级行为不作乐观假设。
4. [腾讯 WXML 条件渲染说明](https://staticintl.cloudcachetci.com/doc/pdf/product/pdf/tencent-cloud_1219_57657_en.pdf)：用条件卸载保证浮层出现时画布节点不存在，不只改变可见样式。

应用 `redesign-existing-projects` 的现有栈审计→定向改造方法；采用 `interaction-design` 的状态反馈、保留布局和按需展开思路。真实兔兔照片就是内容素材，不添加无关装饰图。

## 5. 验证与限制

- `npm run verify:studio`：15组隔离 wx 桩回归，包括卸载确认顺序、多浮层、快速开关、跳转、十模板、构图、文字、图层、旧草稿、保存失败、格式/尺寸和选框契约。
- `npm run verify:miniprogram`：包含原有页面装载、绘图、家庭、AI、连续对话、滚动和原生风格回归，以及上述工坊检查。
- `npm run verify:native-compile`：微信官方 wcc / wcsc 编译 WXML 和 WXSS。
- `scripts/preview-native-studio.mjs --screenshots`：由实际 WXML/WXSS 与原生绘图器生成离线样张，检查320/390/760/1024宽度、10个布局场景与64种旋转/双向翻转/边缘取景组合。原片矩形四角不得露白；目录样张必须没有 Canvas 节点。

离线预览脚本位于开发仓库；原生交付包不携带 Chromium 或前端开发依赖。

这些检查不等于微信模拟器或手机的真实渲染验收。离线图片中的顶部导航为适配示意，绘图作品由实际原生绘图算法生成。微信侧请完整编译后检查：工坊→目录→关闭→豆伴→返回→保存；尤其核对 Android/iOS 的相册授权、高清导出和字体回退。

维护提示：原生 `utils/painter.js` 已独立维护，包含小程序特有的滤镜回退、椭圆替代、马赛克快照和本轮编辑能力。旧 `build-native-painter.cjs` 加入覆盖保护，不能再用落后的 Web 版覆盖它。
