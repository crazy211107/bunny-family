# 兔兔家庭小程序 · 电影感交互版优化提示词

本稿将原始的九组提示词收敛成一份主提示词和分阶段任务。最新增强规格请同时使用《专家增强提示词与功能闭环.md》，编码交接请看《微信小程序设计编码交接.md》。先验证交互，再接入微信能力，避免把视觉效果、数据能力和媒体算法一次性混写。

## 一、可直接复制的主提示词

你是一名擅长可爱手账设计、影像叙事、创意交互和移动产品的设计师与前端工程师。请为一个家庭和两只宠物兔打造「兔兔小窝」。在奶油系可爱手账风里加入电影放映、胶片、场记与故事翻页：每天照顾兔兔，记录家人的小事，把照片变成有温度的家庭回忆。不要做传统工具类小程序的换皮。

**设计优先级：严格遵循原文的奶油系可爱手账风，其次增加电影叙事与创意交互。禁止传统底部导航；保留原文独立的兔耳果冻母按钮和四项扇形菜单。不能将电影感解释为暗色海报、商务界面或衬线大片风。**

### 1. 当前交付范围

先交付可以在浏览器运行的高保真交互原型。使用 React + Vite，移动端优先，同时适配桌面端。原型使用本地存储，禁止将本地演示描述成微信云同步或真实推送。后续再依据已验收界面迁移为微信小程序。

交付完整源码、启动说明、可交互预览、功能边界及验证结果。所有主要按钮必须有明确行为；未接入的能力应说明限制，不能用成功提示伪装成已完成。

### 2. 素材和初始资料

- 使用用户提供的真实兔兔照片，保留毛色、形态和照片本身。不要将任意生成的兔子冒充家庭宠物。
- 用户已确认白色兔兔叫「豆米」，黄色兔兔叫「豆糕」。界面、相册与日记使用稳定 petId 关联，改名不丢记录。
- 附件共八张，其中后三张为同一场景的重复照片，初始相册使用六张去重素材。
- 不从照片推断品种、生日、性别、体重、绝育或健康状态；未知资料存 null，界面显示「待填写」。
- 家庭成员使用明确的演示资料，支持新增、编辑、排序和删除；不虚构真实身份。

### 3. 设计 DNA

- 风格：奶油系可爱手账，真实兔兔大画幅、拍立得、胶片打孔、胶带、便签和故事翻页。电影感来自照片取景、可播放的回忆幻灯片和转场，保持明亮、温暖、可爱。
- 色板严格沿用：背景 #FFF9F0；主色 #FFD9E8；辅色 #C9E7D3；强调 #FFE9A8；正文 #6B5B73。所有页面均沿用，不切换成暗色电影主题。
- 背景使用低透明度纸张颗粒；纹理不得覆盖文字、阻挡点击或影响性能。
- 大标题采用圆体 / 手写感中文字体，正文移动端至少 14px，主要触控区域至少 44px。不要用严肃大片衬线标题替代可爱风。
- 卡片采用四组固定非对称圆角，配细可可色描边与轻微纸张投影。卡片宽度、留白和角度按页面规则变化，不在每次渲染时随机。
- 倾斜角主要限于照片、胶带和装饰，表单与正文保持端正。禁止为非对称牺牲阅读顺序。
- 主要图形为兔耳、爪印、胡萝卜、爱心；不使用和兔兔主题无关的骨头装饰。
- 不使用商务蓝、底部 tabBar、传统底部导航、常规侧栏仪表盘或每页相同的等宽卡片网格。可以使用有语义的双兔选择器和四项照顾按钮。
- 导航采用右上角「翻开目录」打开全屏故事目录，提供「手账墙 / 兔兔档案 / 家庭成员 / 创意工坊 / 回忆相册」。底部仅保留独立兔耳果冻母按钮，点击向上展开拍照 / 录视频 / 记一笔 / 召唤兔兔四项扇形快捷动作，绝不铺设底部导航条。
- 首页标题「我们家 ♡」配薄荷色手绘下划线，右上角黄色日期便签。主视觉「小日子，慢慢放映。」搭配可播放的兔兔照片拍立得。页面以不对称拼贴延续今日照顾、待办和回忆照片，功能卡与照片大小、圆角、边距至少两项有变化。
- 动效采用短暂的按压回弹、抽屉进出和完成反馈。支持 prefers-reduced-motion；避免所有元素一直晃动。

### 4. 页面和核心闭环

#### 首页「手账墙」

以「我们家 ♡」「小日子，慢慢放映。」和双兔合照作为可爱的手账放映开场。点击「翻开今日手账」打开奶油纸场记抽屉，里面包含当前日期、兔兔照顾摘要、待办和日记。

- 拍立得点击进入相册详情，可前后浏览、标记喜欢、送入照片工坊。
- 点击兔兔摘要进入对应兔兔档案。
- 待办可新增、完成和删除，操作后立即反映到页面并持久化。
- 兔耳母按钮提供「拍照片」「录视频」「记一笔」「召唤兔兔」。拍照在浏览器中使用本地图像选择；取消选择不报错。录视频进入视频草稿流程；记一笔保存标题和正文；召唤触发短暂互动反馈。
- 移动端如实现下拉刷新，只更新实际数据；兔兔动效为反馈，不代表触发云同步。

#### 兔兔档案

- 两只兔兔切换，共享清晰的页面结构，数据按 petId 隔离。
- 档案可编辑昵称、生日、品种说明和绝育状态。体重来自独立的体重记录，不写死演示数值。
- 「喂草 / 换水 / 铲屎 / 陪玩」四项按本地日期独立打卡，保存真实操作时间，可撤销。再次点击不得产生重复记录。
- 显示今天完成数。连续七天均完成四项才解锁「兔兔守护者」，没有历史记录时不得伪造连续天数。
- 体重输入正数 kg，保存两位小数；支持同日记录更新与删除，图表和记录列表同步。
- 健康提醒只展示用户设置的事项与日期。到期日不足七天突出显示，过期显示「已逾期」，未设置时显示空状态。不得默认宠物兔必须按某个固定周期接种或驱虫。

#### 家庭成员

- 以手账时间轴展示家人，支持添加、编辑、删除与排序。
- 编辑使用右侧抽屉，手机为全屏；有明确的关闭和保存按钮。
- 字段：头像、昵称、角色标签、生日、与其他成员的关系。
- 生日为可选资料，未设置不计算倒数；生日倒数按月日计算，考虑闰日。
- 排序提供拖拽及按钮备选操作。关系先通过成员选择与关系文本编辑，手势连线为后续增强，不作为唯一输入方式。

#### 回忆相册与照片工坊

相册支持照片预览、喜欢、分类筛选与编辑入口。工坊形成「选图 → 选模板 → 编辑 → 导出 / 保存回忆」闭环。

- 八个模板：拍立得、撕纸胶带、四格拼贴、手账贴纸、双重曝光、镜像、波点漏光、日期拍立得。
- 模板必须实际改变输出。双重曝光可选择真实副图；未选择时使用同图半透明叠影。四格拼贴可为每个槽位选择独立照片。
- 编辑支持标题文字、日期、兔耳 / 胡萝卜 / 爱心贴纸、亮度 / 对比度 / 饱和度、马克笔 / 荧光笔 / 虚线笔 / 马赛克；提供复位、30步撤销重做、草稿保存恢复。
- 贴纸可拖拽、缩放、旋转和删除。桌面保留按钮或滑杆备选操作，不让双指手势成为唯一方式。
- 原型手动添加兔耳；人脸识别后的自动定位属于后续能力，禁止把固定位置叠图称为人脸识别。
- 使用 Canvas 导出真实 PNG；导出分辨率为预览的两倍。导出内容必须与预览一致，包括模板、文字、贴纸和调色。
- 保存回忆需能在相册重新打开；上传图片在本机浏览器保存，存储失败必须提示，不能假报成功。

#### 视频草稿

- 原型可选择本地视频、原生播放、编辑标题、选择滤镜及字幕文本、保存草稿。
- 明确区分预览、草稿与真正导出的成片。浏览器原型不承诺 MP4 合成、语音识别、人物跟踪或版权音乐。
- 正式版本再评估六十秒素材、十五秒分段、时间轴裁切、转场、字幕识别与服务端合成。
- BGM 只能使用具有可核查许可的素材，不能把风格描述当成免版权证明。

### 5. 数据和状态约束

- 状态采用统一 store，通过 ID 引用对象；不在路由参数中传大对象。
- checkins 以 petId + localDate + type 唯一；体重记录按 petId + date 更新。
- 日期使用设备所在地日历日期，展示与存储规则保持一致，不直接用 UTC 日期切片判断「今天」。
- localStorage 存小型结构化资料；IndexedDB 存照片和视频 Blob。需要处理存储空间不足、损坏数据和媒体读取失败。
- 用户照片不上传到第三方服务器，除非后续明确启用云相册。
- 对用户输入进行正常文本渲染，不作为 HTML 执行；禁止在前端保存云密钥。
- 初始演示内容与用户新建内容区分，刷新保留用户操作，不自动重置数据。

### 6. 组件和实现结构

建议按页面与业务拆分：AppShell、HomeJournal、PetProfile、FamilyTimeline、MemoryAlbum、PhotoStudio、VideoDraft，以及独立的状态、日期和媒体存储模块。

复用组件：ChapterMenu、SceneFrame、MomentMenu、TapeButton、BlobAvatar、PolaroidCard、StickyNote、CheckinGrid。电影场景通过布局、字体、影像与真实交互实现，不通过整页背景截图伪装。

- JellyButton：短暂按压回弹，disabled 和 focus-visible 态清楚。
- BunnyFAB / MomentMenu：独立粉色果冻母按钮带兔耳，点击展开四项扇形快捷动作，支持 Escape 关闭及 aria-expanded。底部没有导航条。
- TapeButton：用胶带装饰保存动作，胶带不覆盖点击区域。
- BubbleButton：轻量气泡反馈，低动效模式静止显示。
- ChargeButton：可选长按仪式感交互，同时提供点击替代；取消按压后清零。
- 所有图标按钮具有无障碍名称；抽屉管理焦点并支持 Escape；键盘可完成主要操作。

### 7. 原型验收标准

1. 375 / 390 / 768 / 1440px 宽度下可正常浏览，无横向溢出；没有传统底部导航条；目录入口和独立兔耳快捷菜单可发现，末项内容不被遮挡。
2. 四个主要栏目可切换，返回与抽屉关闭不丢失已保存内容。
3. 两只兔兔打卡各自独立，刷新保留，同一项目可撤销。
4. 待办、成员、档案、体重、健康提醒和日记的保存可在界面查证。
5. 六张初始照片无重复文件；相册预览、喜欢、模板切换与实际图片导出有效。
6. 图片导出中能看到文字、调色和用户贴纸，导出的 PNG 可再次打开。
7. 上传取消、空数据、错误输入、存储失败有明确反馈；页面无未处理异常。
8. 对未接入的微信能力和视频能力如实说明，不出现虚假成功状态。
9. 用实际浏览器验证关键流程并检查手机截图，代码可成功构建。

## 二、后续分阶段提示词

### 阶段 A：原型视觉与交互

依据上面的主提示词完成浏览器原型。先实现可爱手账放映开场和故事目录，再打通场记抽屉、家庭成员、双兔打卡、回忆放映及照片工坊。严格保留原色板和异形贴纸设计，优先验证可爱风、创意电影叙事、可用性、真实保存和手机布局。不要增加传统底部导航条、常规侧栏仪表盘、登录、账单、商城、聊天或与需求无关的模块。

### 阶段 B：迁移微信小程序

在已验收原型基础上迁移 WXML / WXSS / JavaScript / 微信 Canvas。先核对当时官方文档、基础库和真机能力，再替换文件选择、授权、相册保存、页面切换和云数据适配层。网页的 CSS、SVG 滤镜、字体和指针手势不可假定原样兼容。保留同一信息架构与视觉 token。

### 阶段 C：家庭云数据与权限

实现 families、members、pets、checkins、weightLogs、reminders、media、notes 集合。各记录含 familyId、createdBy、createdAt、updatedAt；宠物子记录额外含 petId。以服务端校验的家庭成员资格限制读写，不能依赖前端过滤实现权限。处理重复打卡、并发更新、文件删除和数据导出。提醒必须在用户订阅授权及平台规则允许的前提下发送，不能承诺每日固定时间必达。

### 阶段 D：媒体增强

网页原型已接入涂鸦、马赛克与多图混合；微信迁移时验证对应 Canvas 能力。其余双指贴纸、人脸定位、分段录制、裁切、字幕识别、转场和 MP4 合成先做可行性验证再接入。普通云函数是否支持所需计算、FFmpeg 和运行时资源，须按部署环境验证；需要时独立使用受控媒体服务。所有异步任务提供真实进度、失败重试和取消，不把排队当作完成。

## 三、原稿关键调整

| 原始表述 | 优化结果 |
| --- | --- |
| 每张卡随机圆角和宽度 | 固定四组样式，保持拼贴感和布局稳定 |
| 传统底部导航 | 顶部故事目录 + 独立兔耳果冻母按钮的扇形菜单 |
| 一次实现全部照片 / 视频算法 | 原型、微信迁移、媒体增强分阶段验收 |
| 一键兔化等于人脸识别 | 原型手动贴纸，真实识别单独接入 |
| 云函数每日 20:00 必定推送 | 以授权、订阅额度及平台规则为条件 |
| 宠物默认疫苗 / 驱虫周期 | 只记录用户自行设置的事项和日期 |
| BGM 默认免版权 | 使用可验证许可的实际素材 |
| 资料及指标自动补全 | 不确定资料为 null，明确待填写 |
| 所有点击持续回弹与抖动 | 关键动作短反馈，支持低动效模式 |

本地原型最终实现范围与操作方式详见项目 README。
