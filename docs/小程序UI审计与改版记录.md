# 小程序 UI 审计与改版记录

> 2026-10-27。审计对象：`miniprogram/` 七个页面 + 三个组件。
> 方法：真实微信编译器编译 + `miniprogram-automator` 模拟器截图 + 源码规则扫描。

## 一、三个全局根因

### 1. `app.json` 的 `"style": "v2"` 把全站 `<button>` 拉满宽度

**症状**：播放键、下一张、兔耳悬浮球、家人编辑按钮全变成横条椭圆；家人卡片里的名字和角色被挤成竖排单字。

**原因**：v2 组件风格下 `<button>` 默认按容器宽度铺开，页面 WXSS 里写死的 `width:57rpx` 不生效，只有 `height` 生效，于是 `border-radius:50%` 把方块拉成椭圆。

**处理**：移除 `"style": "v2"`，改由 `app.wxss` 统一复位按钮样式。一处改动同时修好了首页、家庭、相册、日记四页。

**教训**：这类问题编译器不报错，只能靠肉眼验收。

### 2. WXML 指令漏写双花括号（14 处）

`wx:if="journal"` / `wx:for="pets"` 会被当成非空字符串（恒真），导致抽屉永远打开、列表永远渲染不出来。已全部补成 `{{ }}`，并在 `scripts/verify-miniprogram-pages.mjs` 里加了扫描规则。

### 3. `project.config.json` 缺 `miniprogramRoot`

开发者工具打开仓库根目录时找不到 `app.json`。已补 `"miniprogramRoot": "miniprogram/"`。

## 八、图片 500 报错定位（关键修复）

**现象**：控制台报
`GET /__pageframe__/pages/studio/assets/photos/doudou-close.jpg 500`

**判断依据**：请求路径里出现了 `pages/studio/` 前缀，说明 `<image src>` 被当成**相对页面目录**的路径解析。若 `src` 以 `/` 开头，小程序按包根解析，不会出现页面目录前缀。

**结论**：本地存储 `bunny-family-native-v1` 里遗留了不带前导斜杠的 `src`（`assets/photos/xxx.jpg`）。`store.get()` 用 `Object.assign` 合并存档，这些旧值会一直覆盖 `initial()` 里正确的 `/assets/...`，于是每次进工坊都 500。

**修复**：`utils/store.js` 增加 `fixAsset()` 与 `normalizeAssets()`，读取存档时统一补齐前导斜杠，覆盖 `photos[].src` / `pets[].photo` / `members[].avatar`；`getPhotoSource()` 同样走归一化。已写入的旧数据在下次 `update()` 时被纠正。

## 十、第三轮：参照开源规范的自研改版

**参照**：GitHub 连接器不可用，改用 `raw.githubusercontent.com` 直接取 Vant Weapp 的 Button 文档。其尺寸体系为 large / normal / small / mini 四档，normal 为 44px。本项目主按钮 88rpx（44px）与之对齐，次级 76rpx（38px）、胶囊 64rpx（32px）形成三级。同时参考公开的瀑布流实践结论：**卡片高度必须确定性**，随机或按图真实比例会在刷新后错位，因此胶片卷采用固定帧尺寸而非自适应高度。

**改动**

1. **工坊移除全局兔耳悬浮球**：它固定居中在屏幕底部，正好压住「模板/贴纸/涂鸦/文字/调色」页签，导致核心工具点不到。工坊有顶部目录入口，不需要这枚球。
2. **首页回忆条 → 胶片卷**：老式「小拍立得卡片」换成带齿孔（sprocket）的胶片帧，帧内左下角有编号，奇偶帧反向微旋转，整卷可横向滚动。视觉上把「电影感」从文案变成结构。
3. **相册按月归档（新功能）**：照片按 `date` 前 7 位分组，输出「2026 年 10 月 · N 帧」的组头（左侧粉色竖条），无日期的归入「还没写日期的片段」。分组在 `refresh()` 里一次算好，模板用 `block` 嵌套循环渲染。

**验证**：编译器通过 963.4 KB；7 页装载、WXML 指令扫描、绘图管线断言全绿；相册 WXML 标签与 `block` 配对检查通过（5/5）。

**未完成**：本轮仍未取得相册与首页的模拟器截图（自动化 `currentPage` 超时）。

## 十二、胶囊遮挡修复 + 长按多选

**问题**：抽屉右上角的关闭 × 被微信原生胶囊盖住，点不到（用户截图实证）。

**根因**：微信右上角胶囊是原生控件，层级永远高于 `view`，任何放在该矩形内的元素既看不见也点不到。`.drawer` 原来只用了 `env(safe-area-inset-top)`，它只描述状态栏高度，不包含胶囊。

**修复**：`app.js` 启动时算一次 `safeTop = capsule.bottom + 8`（取不到胶囊时回退 `状态栏 + 44`），存进 `globalData`。五个页面的抽屉、相册放映层、兔耳菜单的故事目录书页，全部改用内联 `style="padding-top:{{safeTop}}px"`，内容整体下移到胶囊之下。

**新功能**：相册支持**长按照片直接进入多选**（`bindlongpress`），并自动把该照片选中、给出提示，符合小程序列表的常见手势习惯。

**验证**：临时让首页抽屉默认展开截图，确认标题与 × 已落在胶囊下方；随后恢复默认收起。编译 966.9 KB 通过，7 页装载通过。

## 十三、顶部留白过大的真正原因

**现象**：抽屉头部与微信胶囊之间空出约 150px。

**实测数据**（真机日志）：`statusBar=39`、胶囊 `{top:37,height:32,bottom:69}`、计算得 `safeTop=77`。77 是对的，但屏幕上是 150+。

**根因**：给 `.drawer` 批量加内联 `padding-top` 时用了 `class="drawer..."` 前缀匹配，结果 **`.drawer-head` 也被命中**（同样以 drawer 开头）。两层 77px 叠加，才有了那道夸张的空白。

**修复**：只保留 `.drawer` 上的 `safeTop`，`.drawer-head` 恢复紧凑内边距（16rpx）。同时给 `safeHeaderTop()` 加了上限 `statusBar + 48`，避免个别机型按物理像素返回胶囊矩形时再次把内容推飞。

**结论**：安全区计算不是越大越安全，重复叠加才是真正的坑。

## 十四、兔兔档案重做：从卡片堆叠到「档案册」

**原来的问题**：页面是五个同质化卡片的垂直堆叠（介绍卡 / 汇总卡 / 热度卡 / 月历卡 / 记录卡），信息密度平均，没有主角；名字和头像缩在卡片里，看不出「这是豆米的档案」。

**新版结构**（`pages/pets`）

1. **封面页**：整张兔兔照片铺满 470rpx，顶部奶油底小标签 `RABBIT FILE` + 品种胶囊，底部渐变压暗后放名字与三项指标（今日照顾 / 连续天数 / 近 7 天次数），中间用发丝竖线分隔。
2. **档案栏**：四格两行（身份 / 年龄 / 体重 / 绝育），用虚线分隔而不是四个独立卡片，末尾一枚虚线描边的「完善这份档案 ↗」。
3. **今日照顾**：2×2 大格（150rpx 高），四色底（薄荷 / 藕粉 / 奶油黄 / 樱粉），完成后整格变绿并显示真实打卡时间；连续天数改为卡底分隔线小字。
4. **照顾节奏**：把原来的「汇总卡 + 热度卡」合成一张——两个数字块（近 7 天次数、四项全完成天数）+ 14 根热度条。
5. 月历、当日场记、体重、健康提醒保留原结构与交互，只随新卡片尺度对齐。

**可读性修正**：封面上的品种文字原本是半透明白字压在浅色照片上几乎看不见，改为奶油底胶囊；渐变遮罩加深到 72% 处开始转暗，名字加描影。

**验证**：编译器 972.6 KB 通过；模拟器截图确认封面、档案栏、今日照顾三块的排版与对比度。

## 十六、对标开源产品的新功能与设计落地

### 参考分析

GitHub 小程序生态里 `topic:weapp` 按 star 排序，前 10 名几乎全是**框架与组件库**（WxJava 33k、wepy 22k、mpvue 20k、vant-weapp 18.5k、iview-weapp 6.6k、wux 5k、westore 4.3k），没有成熟的照片手账类应用可抄。所以功能层面对标的是三个成熟的开源/商业照片产品：

| 参考 | 它们的做法 | 本项目落地 |
| --- | --- | --- |
| Immich（开源相册） | Memories：按「多年前的今天」聚合旧照片，自动推送到首页 | **去年的今天**：按 `MM-DD` 匹配历史照片，首页卡片展示 3 张 + 年份角标 |
| Day One（日记） | On This Day + 心情标签统计 | **心情分布**：按月统计各心情篇数，横向条可视化 |
| PhotoPrism | 时间轴 / 相册集 / 标签 | 已实现按月归档 + 标签筛选 |

### 新增功能清单

1. **去年的今天**（首页）：从相册里筛出与今天同月同日、但年份不同的照片，按日期倒序取 3 张；标题显示「N 年前的今天」，缩略图带年份角标，点击直接进系统大图预览；无数据时整卡不渲染，不占位。
2. **心情分布**（日记）：对当前筛选结果做心情聚合，按篇数排序输出横向进度条，最少 8% 宽度保证可见；只有一种心情时不显示（没有对比意义）。
3. 此前已完成：相册按月归档、全屏放映（自动播放 + 进度条 + 点击暂停）、长按照片进多选、14 天照顾热度条、胶片卷、档案册封面。

### 设计亮点

- **数据门槛**：两个新功能都只在「有数据且有意义」时出现（去年今日需跨年同日；心情分布需 ≥2 种心情），避免空卡片堆满首页。
- **信息即交互**：年份角标、进度条都是真实数据驱动，不放装饰性假数字。
- **视觉语言统一**：记忆卡用奶油黄（区别于粉色主卡与绿色打卡），心情条用「樱粉→薄荷」渐变，与体重条同源。

**验证**：编译器 981.5 KB 通过；「去年的今天」用临时全量数据截图确认排版（三列缩略图 + 年份角标 + 标题层级），随后已还原为真实筛选逻辑。

## 十七、多角度改版（层次 / 排版 / 动效 / 细节）

一次改四个维度，而不是逐个按钮调：

**层次**：首页封面加「叠纸」——底下压一张旋转 -2.6° 的衬纸（`.hero-underlay`），右侧与底部各露出 16–20rpx；照片内嵌 1rpx 奶油描边并加 `NO.1 / 6` 角标。全局 `.paper-card` 阴影升级为三段（内高光 + 硬投影 + 柔投影），卡片从"贴纸"变成"纸张"。

**排版**：`.section-title` 字距 2→3rpx；卡片内边距统一 28–30rpx；区块间距 40rpx 基线。

### 采纳的提案（2 条，均已实施）

**提案 1：画布不再逐帧重分配 + 拖拽节流**
- 参考：Drawing-board 的「多次重绘 canvas」教训。
- 改什么：`utils/painter.js` 的 `renderArtwork`、`pages/studio` 的 `touchMove`。
- 收益：拖拽贴纸/画笔时，原来每帧都给 `canvas.width` 赋值一次，等于每帧重新分配 900×1000 的像素缓冲；现在只在尺寸变化时赋值，并把重绘节流到 40ms（约 25fps），抬手时补一次全量。手感更跟手，真机不易掉帧。
- 技术路径：纯原生改动，不改任何交互与页签结构，不碰硬约束。
- 风险：节流会让笔迹在极快滑动时略显"追赶"，抬手即补齐。

**提案 2：扇形菜单错峰展开 + 遮罩淡入**
- 参考：Leaf Island 的「温和微交互」——只取其节奏思路，数值仍用本项目既有的 `cubic-bezier(.34,1.56,.64,1)` 与 350ms。
- 改什么：`components/bunny-menu` 的 `.action` 过渡延迟与 `.fan-mask`。
- 收益：四项从"一起弹出"变成"依次弹出"，收起时不延迟，动作有先后感。
- 风险：仅 CSS，`prefers-reduced-motion` 仍然生效。

## 十九、照顾线：把三张卡合成「今天要记得的」

**问题**：待办在首页、健康提醒在档案页、今日打卡在档案页顶部——同一件"今天该做什么"被拆成三处，用户要来回翻。

**改法**（参考 WoofMeow 的「持续关注事项」信息组织，只取 IA 不取代码）：

1. **健康提醒**（3 天内到期，含逾期）— 红色 `!` 标记，右侧显示「逾期 2 天 / 就是今天 / N 天后」

## 二十一、玻璃拟态：范围、参数与降级

### 一条边界

**纸卡不变玻璃，玻璃只给浮层。**

这个项目的气质是"摊在桌上的手账纸"，内容卡片一旦半透明模糊，纸感就没了。所以玻璃只用在"浮在纸上的东西"：悬浮球、遮罩、目录书页、放映信息条。

### 组件范围（4 处，不多不少）

| 组件 | 玻璃处理 | 理由 |
| --- | --- | --- |
| 兔耳悬浮球 `.fab` | 粉白渐变半透明 + `blur(18rpx) saturate(160%)` + 外描边环 + 上内高光/下内阴影 | 它是唯一常驻浮在内容上的元素，玻璃能读出"悬浮" |
| 扇形遮罩 `.fan-mask` | `rgba(255,249,240,.55)` + `blur(10rpx)` | 展开时页面退到后面虚化，焦点收在四个动作上 |
| 故事目录 `.directory-mask` / `.directory-sheet` | 遮罩 `0.72` + `blur(14rpx)`，书页本身仍近实色 | 目录是"翻开的整页"，卡片可以透，正文必须实 |
| 放映顶栏 / 信息条 `.theater-bar` / `.theater-caption` | 深紫 `rgba(59,49,64,.42)` + `blur(16rpx)` + 白色 1rpx 描边 | 压在照片上，玻璃比纯色条更轻，不切断画面 |

参数统一：`inset 0 1rpx 0 rgba(255,255,255,.95)` 内高光 + `0 10rpx 28rpx rgba(107,91,115,.13)` 外阴影 + 1rpx 白描边，三层一起才像玻璃而不是半透明色块。

### 降级策略（关键）

微信小程序里 `backdrop-filter` 在 Android 大面积不支持。所以玻璃不能依赖模糊：

- 底色透明度控制在 **0.42–0.88**，没有模糊时仍是一层实色罩，文字可读；
- 描边与阴影不依赖模糊，任何机型都有；
- 正文永远不用玻璃承载，只做背景层。

### 性能约束

- 模糊只加在 4 个浮层，**没有一处用在列表项上**（列表里几十个元素都开 blur 会直接掉帧）；
- 任意时刻同屏玻璃层 ≤ 2；
- 遮罩只在展开态存在（`wx:if`），关闭即销毁，不常驻。

### 交互补充：目录下拉收起

原来只能点右上角 ×。现在书页顶部有 8rpx 的抓握条（grabber），在**头部区域**下拉超过 90px 即收起。
手势只绑在头部，不绑整个 sheet——否则用户正常向下翻目录时会被误关。

### 验收标准

1. 编译器通过，包体 < 1.1MB（当前 989.8 KB）。
2. `verify-miniprogram-pages.mjs` 7 页装载 + WXML 指令扫描通过。
3. 正文不落在玻璃层上；浮层内文字对比度不低于同页纸卡。
4. 触控尺寸不因玻璃化变小：主按钮仍 88rpx，悬浮球 104rpx，目录关闭键 68rpx。
5. 无 `backdrop-filter` 的机型上，浮层仍是可辨识的实色罩，不出现"透到看不清"。
6. 同屏玻璃层不超过 2 层。
7. 真机需验收：目录下拉收起、悬浮球展开/收起、放映层暂停与切帧。

**验证状况**：1、2、4 已通过（编译 989.8 KB、7 页装载、尺寸未改）；3、5、6 属静态判断，代码层面成立；7 与整体观感**未做截图验收**——automation 本轮持续超时。

### 八、事故复盘：`@import "./styles/..."` 导致全局样式全部失效

**现象**：开发者工具报 `path './styles/base.wxss' not found from './app.wxss'`。

**根因**：WXSS 的 `@import` **不接受 `./` 前缀**。写错时不会"少加载一个文件"，而是整条导入失败，等于 `base / components / responsive` 三层全部没进包——全站看起来会像"样式丢了"。

**为什么我没发现**：上一轮我只看了 `cli.bat preview` 返回的 `√ preview`。CLI 编译器对这种路径比 IDE 宽松，所以它通过了，但 IDE 编译失败。**`√ preview` 不等于样式已生效**，这是我这次的判断失误。

**修复**：
1. `app.wxss` 改为 `@import "styles/base.wxss";`（无 `./`）。
2. `scripts/verify-miniprogram-pages.mjs` 新增「样式入口」检查：解析所有 `@import`，逐个检查文件是否存在、是否带 `./` 前缀。这条检查就是为了让同类错误在提交前暴露。
3. 顺带把 `empty-state` 从全局 `usingComponents` 下沉到 4 个页面的 `index.json`，全局组件从 4 个降到 3 个——对应开发者工具的「全局自定义组件影响按需注入」提示。

**复验**：`@import 3 个 ✓`；编译器 989.5 KB（若导入失败会掉到 ~981 KB，说明样式确已入包）；7 页 + 4 组件装载通过。
