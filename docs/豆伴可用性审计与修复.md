# 豆伴 · 可用性审计与修复

2026-10-29。按用户确认的第三阶段方案实施，沿用微信原生 WXML/WXSS/JS 与奶油粉绿品牌，没有引入依赖或修改 AppID。

## 根因、改动与状态

| 问题 | 证据或根因 | 本轮改动 |
| --- | --- | --- |
| 新对话不突出、难点击 | 原入口混在次级工具栏，高度80rpx；375px宽设备仅约40px；空会话重建没有可感知反馈。改前的精确命中失效根因未能回溯 | 移至顶部固定独立 button，至少44px，返回/更多独立；空会话复用并聚焦及轻提示；保存失败保留旧会话；用户编译后确认可正常新建 |
| 首屏信息过载 | 三个资料入口、大欢迎区、三个示例；配置卡仅判断消息为空，已配置也出现 | 历史/资料/连接收进更多；两个示例，只在没有密钥时显示连接引导；高级设置与资料正文按需展开 |
| 新建丢草稿 | 直接清空输入，未按会话保存 | 新建、收起、切换时保存当前输入，草稿会话也能从列表找回；保留本机历史时旧消息保存失败阻止切换 |
| 回到最新时屏幕跳动 | 程序滚动事件可能被判为用户上滑；最新按钮处于flex布局流，显隐改变消息区高度，形成反馈 | 独立消息区，最新按钮绝对定位；显隐不挤压布局；程序回底/键盘重排与用户手势分开；回底更新合并，同状态滚动事件不重复setData |
| 流式更新重算历史 | 每个分片重建所有可见消息 | 只更新正在生成的回答，已完成消息不重新解析和下发 |
| 历史不可展开 | 只显示末30条并给出隐藏提示 | 增加加载更早消息、保留锚点；超长内容按受控窗口分段，可返回最新 |
| 异步串线 | 选择图片返回时未核对会话 | 会话与选择令牌校验，旧选择结果丢弃；停止请求后迟到回答不能写入新会话 |

## 返回与状态

对话→会话列表→来源页；设置/资料预览回到原会话。更多展开时返回先收起更多。更多菜单位于Header下方，不覆盖新对话，也没有全屏透明遮罩。输入为空或纯空格时禁用发送；等待、流式、停止、错误、重试反馈保留。没有配置密钥时仅给连接引导，不伪造可用状态或AI回答。

会话只在本机保存。当前组件内的未发送草稿可切回恢复，未承诺跨进程草稿持久化。模型最多携带十五轮文字；轮数、范围过滤、历史节选与实际快照在“更多→本次资料与上下文”中查看，不再占主界面横条。

## 验证边界

- 原有22组AI/照片检查保留；新增12组原生可用性检查，覆盖新建/草稿/空会话/存储失败/生成中新建/迟到图片/滚动暂停/键盘/早期历史/增量刷新/菜单返回。
- 滚动回归连续注入150组程序滚动及底部事件，验证不会反复显隐按钮；稳定底部再注入100组事件，不产生多余setData。它是状态回归，不等同真实模拟器帧率测试。
- 微信官方本地编译15个WXML、19个WXSS通过；完整原生回归使用 `npm run verify:miniprogram`，专项使用 `npm run verify:chat-ux`。
- 窗口只读取图确认过中间状态；随后窗口最小化，未展开或移动鼠标，未取得最终状态截图。用户完整编译后，明确回复“回到最新”与顶部“新对话”两项都正常，这是模拟器人工功能反馈。尚未完成真机、键盘/读屏或帧率测量；本轮自动测试没有调用真实模型服务。

完整点击开发者工具“编译”后验证顶部新对话，以及长会话上滑→回到最新→继续输入；避免仅依赖热重载保留的旧滚动位置判断。
